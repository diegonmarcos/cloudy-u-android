# cloud-c3-webserver

The phone's local web server, as an APK, in the cloud-c3 family: Rust and web only. It is a Tauri 2
Android app: the Rust library in `src-tauri/` starts the web servers on threads of the app's own
process, waits for the bind, and opens the app's one webview on its shell, `http://127.0.0.1:8002/__app__/`.

**The app is five tabs around the file view.** Pages, API, Home, SSHd, Configs (`server/ui/shell.html`, served
under `/__app__/` only). The file view at `/` is the shared server's, unchanged and shell-free (no longer embedded in a tab). The tabs are the
rows of `server/src/app.rs::ROUTES` that carry a caption, so a row added there appears and a row removed
disappears. Pages lists every served page by port and private name; API lists the shell's routes; Home is the
About-this-phone page in the SuperApp's Configs > About shape; Configs has About, Engines (read-only registry,
`build.json::render_engines`) and Links.

**Links.** Any link the web server serves (rendered Markdown and listings in the file view, the Pages tab)
asks first: *Open in browser* (cloud-browser, explicit-package intent via `POST /__app__/api/open`) or *Open
embedded* (this app's WebView, so the system back gesture follows the WebView history, then falls back to the
app). Link types, their choices and whether a choice can be remembered are `build.json::links`; the shell holds
no type. A remembered choice lives in the WebView's localStorage; Configs > Links resets it.

**Sub-pages (#1490).** API has MCP (the MCP tool catalogue of all our APIs, generated by data/gen_mcp_catalogue.py, #1495), Public Endpoints, Mesh Endpoints, Apps Endpoints and Apps IPC; Pages has Drive, Terminals and
Repos. They are declared in `build.json::subpages` and every one is a route `/__app__/api/sub/<tab>-<id>` answering one page shape
(`server/src/apis.rs`, `server/src/sub.rs`); the shell draws them all with one renderer. The data is read from declarations that exist
(fleet endpoints, the debug-port table, the fleet manifest), never typed per app.

**Pages tab.** One list of the pages actually served (`server/src/served.rs`, `GET /__app__/api/served`): the four declared endpoints
(Termux, Nix, Local, Cloud), the places added below and the ports adopted from the checker. Each row has Status (serving on/off; Termux and
Nix also app open/not open and Start app), Metadata (auth, exposure, host), Source and Links, and its own Start/Stop serving. Local and Cloud
stop by a persisted pause (503) because this app owns them; Termux and Nix are the terminals' own my-webserver, which this app cannot stop,
so only Start app (launch) is offered. "Add a place to serve" is the Repos add API (`POST /__app__/api/repos`, any folder or file of a source,
"Add & serve" starts it). "Undeclared served pages" lists loopback TCP ports that answer (via /proc/net/tcp when Android allows it, plus the
probe range `build.json::served.probe`) and are in no declaration; Declare adopts one, Stop ends it only when this app holds it. The old
Drive, Terminals and Repos sub-page routes still answer. Tests: `test/test-c3-webserver-served.sh`, `test/render-pages.mjs` (G1-G9).

**Mesh log route.** Every fleet app exports its recent logcat and crash ring through its `<package>.logexport` provider
(`libs:log-export`, signature permission). The mesh listener (`server/src/meshlogs.rs`, `runtime.mesh.port`) serves `/logs` and
`/logs/<app>` by calling it. It binds the phone's mesh address only (resolved from the SuperApp's WireGuard profile, refused unless it
lies in `mesh.cidrs`), answers mesh peers only, and needs the fleet bearer on every path; with no token known it answers 503.

**Repos.** `build.json::repos` plus a JSON store: each entry (source, repo, start folder or entry file) is served on its own port by the
shared web server (loopback, or the mesh address when the entry says `mesh`; never public), started and stopped on its own. Sources are
Emulated storage (read from disk) and the terminals' own my-webserver (a path-guarded GET proxy). Entries may not name `..`, an absolute
path, a backslash or NUL, and a symlink cannot leave the source or the repo.

**What :8002 serves.** ONLY the emulated root, `/storage/emulated/0`, with the EXACT web UI of the
Linux `my-webserver`: folder tree on the left, viewer/renderer on the right (md, json, yaml, html with
Eruda, images, text), toolbar on top (search, hidden files, raw). That UI is not written in this app.
It is `ab_cloud-libs-shared/libs/fleet-webserver`, the one web server of the fleet (termux :8000 and
nix-on-droid :8001 consume the same crate), whose `vendor/` is a byte-identical, sha256-checked mirror
of `cloud-u-linux/da_my-webserver/src`, bundled at build time (nothing is downloaded at runtime).
Refresh it with `ab_cloud-libs-shared/libs/fleet-webserver/sync.sh --from <cloud-u-linux checkout>`; there is
no custom page, route or script of the file view in this directory; the app's own pages are under `/__app__/`.

**Kotlin.** The app has none of its own. Tauri's Android template commits a
three-line `MainActivity` and two gradle plugin classes, and its build writes
the webview classes into `generated/`; `build.json::tauri.glue` pins the first
three by sha256 and `tauri.generated_kotlin` names the rest.
`test/test-c3-webserver-no-kotlin.sh` fails CI, and `build.sh` fails the
build, on any other `.kt`/`.java`.

Build: the ship workflow checks out cloud-u-linux, verifies the vendored UI against it
(`sync.sh --check --from`), runs the shared server's `cargo test` and this crate's, installs the pinned
tauri CLI, the NDK and the Rust Android target, then `./build.sh build`
(`cargo tauri android build --apk --target <abi>`, release profile) and re-signs the APK with the
shared key.

Testers: `test/test-c3-webserver.sh` (the file view is the shared server's, the navigation structure, Tauri shape,
rename ledger), `test/test-c3-webserver-shell.sh` (tabs and link chooser under node), `test/test-c3-webserver-pages.sh`
(every page and the chooser in headless Chrome at A37 density, screenshots uploaded by the ship job), `test/test-c3-webserver-render.sh` (the real server in headless Chrome at
Galaxy A37 density: tree left, viewer right, toolbar on top), `test/test-c3-webserver-ports.sh` (map,
owners, readers, loopback-only DNS), `test/test-c3-webserver-no-kotlin.sh`, plus `cargo test` here and
in the shared server (vendor hash == the Linux copy, every endpoint's contract, parity with the real
Linux server).

## Server and Keep alive (#1503)
Two master controls sit at the top of Home and Configs and persist in `power.json` (build.json::power). Server OFF stops every listener (pages, mesh listener, Repos sites) and frees the ports; the app then opens on a bundled page whose button turns it back ON. Keep alive (default OFF) is the only reason a foreground service, a sticky restart or a boot receiver exists, and only with Server ON. Guard: test/test-c3-webserver-power.sh; state machine tests: server/src/power.rs.

## SSH doors and the jump host (#1565)

This app hosts no sshd. With Keep alive ON, the keep-alive service's start (at boot too) runs the supervisor in `server/src/door.rs`,
which asks the Nix-on-Droid app to start its mesh sshd (the real OpenSSH on tcp 8024, key auth from that app's own
`~/.ssh/authorized_keys`) through that app's exported `MeshSshdService`, guarded by the fleet's `CONSTELLATION_DATA` signature
permission. The supervisor stops a door only if it started it (or on an explicit Stop), never polls, and adds no service.

- **SSHd tab** (replaces Files; `/__app__/tab/files` redirects; the stale Files table is gone): a **Keep alive** On/Off toggle with its live
  ON/OFF status beside it (the same switch as the Server card), then every door in `build.json::ssh_doors` with live state, engine from the
  SSH banner, bind (observed), auth, host app, seen-up, sessions where `/proc/net` is readable, Start / Stop where a hook exists, a
  per-port Mesh-only switch and Copy All. Only three apps may host an sshd, each on its own port: this webserver (`runtime.sshd.port`
  8025, ON by default), Termux (8023, OFF by default) and Nix-on-Droid (8024, OFF by default). The SuperApp hosts none and has no row.
- **Mesh-only** (default ON, one switch per port: `door_mesh_only.<id>` in the power store, `mesh_only` for nix): the nix sshd listens on the WireGuard mesh addresses plus loopback, never `0.0.0.0` / `::`; addresses are
  resolved at each start from the live VPN interface, and with no mesh address it fails closed (no sshd). Loopback stays because it is
  reachable from no network and the helpers below dial it. Each door's badge shows what actually listens: mesh-only or EXPOSED.
- **Helpers** (`fleet-nix`, `fleet-termux`, `fleet-adb`, `fleet-ipc`, rendered from the declaration into `files/bin`): nested ssh to the
  nix (8024) and Cloud Terminal Termux (8023) doors, wireless debugging plus `adb shell` (this app holds WRITE_SECURE_SETTINGS), and
  `content call` / `content query` / `am` for fleet IPC. No UID magic: each routes to that environment's own door so its uid and
  userland stay in force; nothing switches uid or enters another sandbox.
- **Binder IPC and the signature gate**: the nix shell, the Cloud Terminal Termux shell (both constellation-signed fleet apps) and this
  app's own uid all pass the signature-guarded providers; only a raw adb shell (uid 2000) does not.
- **ADB handoff**: the SuperApp keeps its ADB plane and WRITE_SECURE_SETTINGS grant; this app now also holds the permission
  (supersedes #1515's single holder) and can run `fleet-adb` itself.
- Not built: an app-uid sshd inside this app (needs an embedded SSH server) and Termux start/stop supervision (needs a hook in that app).
