# CG-Omniverse

An app of the Lnktree family (#1335), behind the SuperApp's Cloud > Lnktree row. Package `com.diegonmarcos.cgomniverse`, folder `ad_CG-Omniverse` (the `ad_` prefix of the
Lnktree family, declared in `1_cicd/src/data/app-families.json`; the Cloud family is `ac_cloud-<x>`).

Bottom nav: **Avatar | Galaxy | Store** (`build.json::ui`; each is a page kind drawn by `ui/SectionPage.kt`).

* **Avatar** (#1373): the owner's avatar (`app/src/main/assets/avatar/models/owner.glb`, a MetaPerson Creator export converted offline to a
  rigged, meshopt-compressed GLB) in an editor laid out like MetaPerson Creator's mobile UI (dark stage, Home/AI, Rotate, Export GLB/PNG, a
  bottom sheet of option cards over a bar of nine categories), drawn by `libs:cgc-3d` (three.js + three-vrm in a WEB_WORLD view; three.js and
  OrbitControls are Cloud Nav's copies, `copyThreeAssets` in `app/build.gradle`). Categories, cards, the default avatar and the OpenRouter
  "describe your avatar" connector are `data/avatar.json`; the configuration is saved in the `avatar` prefs file (backed up), the user's
  OpenRouter key in the encrypted `cg_omniverse_ai_keys` store. `cg-omniverse-avatar-proof.yml` (dispatch) mutates the lib's rules and walks
  the tab on an emulator.
* **Store**: the worlds of `data/store.json`, GENERATED from `data/fwa.md` by `python3 data/gen-store.py` (never edit the JSON; `--check` is the
  drift check, run by `test/test-store-data.sh`). The same generator writes `res/xml/network_security_config.xml`: cleartext is forbidden except for the hosts of the http-only Store entries, which the tester holds equal. Filters Type / Dimension / Device are multi-select chip rows, all selected by default
  (`Store.kt`; 2D/3D and 3D/Video count as both 2D and 3D, VR Yes as VR Glass and Flat Screen, VR No as Flat Screen only).
* **Models** (#1701): the Store also lists 3D models (Type **Model**, chip "Models"): the House Boat (OBJ) and the DJI S900 hex-rotor drone (STEP, 237 parts), the owner's own files that Hardtech-CAD MCAD (#1695) declares, published in the public LFS repo `hardtech-db-models`. They are declared in `data/models.json` (GLB view address, SHA-256, size, photo, original) and merged into `store.json` by `gen-store.py` after the web worlds (S8 in `test/test-store-data.sh`). Never baked: the card's photo and the GLB view are downloaded at runtime. "Open in Galaxy" opens the model in a Galaxy tab like any world, drawn by `assets/model/index.html` (three.js + libs:cgc-3d's GLTFLoader, `ui/ModelPage.kt`): download with progress and cancel, SHA-256 check (a mismatch is never shown), Cache Storage keyed by address + hash, rotate / pinch zoom / auto-rotate / reset / wireframe, and a reason on every failure. JVM `ModelPageTest`, `StoreTest`.
* **Galaxy**: a browser-style world viewer (#1400): a tab strip of open worlds (close per tab, "+" opens the Store to pick one), the
  selected tab in a WebView (libs:web-core CloudWeb, WEB_WORLD; WebGL, hardware acceleration) with desktop mode, reload, the WebGPU line
  and open-in-browser. Tabs persist (`Tabs.kt`); the first launch opens the declared default tabs, `build.json::galaxy_tabs` (#1711: Cyber City Orion, floor796, Messenger, in that order; Store ids, the build fails on an id the catalogue lacks; with none declared it is floor796 alone), and a device that already has tabs is given the declared ones it never had once, in their declared order at the front (`Tabs.seed`; a tab the user closed is not brought back); a Store world, the `world` extra or
  `cgomniverse://world/<id>` adds or focuses its tab (a world that cannot load gets a fallback card with Open in browser and Reload); a VR world reports whether this WebView has WebXR and otherwise offers the browser for VR.
* Per-world launch rules: `data/world-rules.json` (keyed by Store id) is copied by `gen-store.py` into store.json as `launch_query`, and Galaxy loads `Store.launchUrl(world)`. floor796 declares `old-render`: its default engine pulls a 175 MB F796 file into a worker (held twice, plus a Cache API write), which a phone WebView renderer can fail to hold and then paints nothing, with no console error; the legacy engine streams the viewport's MP4 tiles instead. Delete the rule to get the best-quality engine back. #1694: the floor796 rule is now declared `"off": true` (gen-store skips an off rule), so Galaxy loads the plain address exactly like Cloud-Browser, which renders it on the same phone; the tile engine's MP4 Range requests were aborted and re-asked by the WebView (net::ERR_FAILED), and the pinned intercept never answers a CDN host or a media Range request. A rule may also declare `grace_s` (store.json `render_grace_s`, #1694): how long the render check treats a flat world as still loading; floor796 declares 240 s because it loads a 175 MB scene file before its canvas exists, and the 20 s default made the check reload it in the CPU presentation, which restarted that download. A rule may also declare `cpu_query` (`launch_query_cpu`): the address of the CPU presentation (#1657), which floor796 sets to none, so its canvas engine is what a CPU-backed canvas shows. Evidence: headless Chromium paints both paths and needs no SharedArrayBuffer, WebGL, WebGPU or cross-origin isolation (floor796 is Canvas2D only), so those are not the cause.
* Pin offline (#1711): the pinned copy never stands between a live page and the network. Before, every request the copy could not answer (and every document) was fetched by the app itself inside the WebView's request, with a second HTTP client. floor796's first data request, `data/matrix.json?r=<random>`, is a new address on every load, so it could never be in the copy and the scene waited on that client or on an origin that did not answer: the top bar over a flat #101010 page, 0 canvases, 0 failed requests, 0 console errors (reproduced in plain Chromium by holding that one request, and on the emulator by dropping the origin's address: `cg-omniverse-f796-cdp.yml`). The rule is web-core `PinPolicy` (pure): what the copy holds is served cache-first as before; what it does not hold, a document and everything on Reload are loaded by the WebView's own network stack and stored afterwards by one background thread (`PinRecorder`), never in the request. When the live document does not arrive within 8 s, or fails (offline), and the copy holds it, Galaxy loads the world from the copy (the host line says "pinned copy"; Reload asks the live site again): the copy then also answers an address whose query was never stored with the newest stored query of that path. The copy itself is written whole or not at all (temp file + rename, one writer at a time: parallel WebView requests no longer lose each other's manifest entries), an entry is served only when its blob holds every byte, and a path keeps its newest 4 queries instead of one more per load. Page diagnostics shows what pin offline did with the latest requests (served from the copy, left to the network, stored), also in logcat (tag `CloudWebPin`; the render verdicts under `CgoRender`). JVM `PinPolicyTest`, `SiteCacheTest`. Measured since: floor796 creates its canvas as soon as `data/matrix.json` answers and then loads only the viewport's tiles (8 files of 1 to 3 MB on a phone), not a 175 MB file; the 0 x 0 canvas of #1694 was the zero-height viewport fixed in web-core.
* Render check (#1657): a world that stays grey says why. `RenderProbe` (pure) compares what the page drew (measured in the page: animation frames, canvases read back, video frames decoded, its viewport) with what the screen shows (a PixelCopy of the world's area, so GPU layers count as the user sees them) and names the failed stage: no content size, no frames, canvases blank, videos not decoding, or the page drew and the WebView is not showing its canvas / video layers. A world that did not reach the screen is loaded once more in the CPU presentation (every 2D canvas CPU-backed from document start, `RenderProbe.CPU_CANVAS_JS`, and the world's `cpu_query`), which is remembered for that world once it is seen on the screen (Page diagnostics has the way back to the GPU layers). Galaxy shows a loading line until the first frame and a banner with the reason (Diagnostics, Reload, Open in Cloud-Browser, Hide) when nothing rendered; the verdict is also in the Page diagnostics sheet and in Configs > X-Ray App. #1711: the canvas contexts a page creates are counted from document start (`RenderProbe.CONTEXT_JS`), so a scene on a canvas outside the document (Messenger's three.js canvas sits in a closed shadow root) is no longer read as "no canvas: its scene never started"; the sheet shows the count. JVM `RenderProbeTest`.
* Tests: `test/test-lnktree-app.sh` (family template `1_cicd/src/templates/test-lnktree-app.sh`), `test/test-store-data.sh`, JVM `PagesTest`,
  `StoreTest`, `AvatarTest`, `TabsTest`, `PinPolicyTest`, `SiteCacheTest`, `RenderProbeTest`. `cg-omniverse-proof.yml` (dispatch) proves the filter, tab and pin-offline tests against planted mutants and takes emulator screenshots. `cg-omniverse-f796-cdp.yml` (dispatch) is the render check of Galaxy's default tabs on emulators (API 34 and 36, over DevTools): Cyber City Orion, floor796 and Messenger must each hold a canvas and show it on the screen, and floor796 must still render from its pinned copy while its origin's address is dropped.
