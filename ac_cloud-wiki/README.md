# Cloud Wiki

A small encyclopedia of short, neutral, educational Markdown pages (#1778). Tile `Wiki` leads Cloud > Apps > Projects (`Wiki | SuperApp, Omniverse | FinTerm, BioMed, CAD | Circusverse`).

* Package `com.diegonmarcos.cloudwiki`, image `cloud-wiki`, asset `Cloud-Wiki.apk`, ship workflow `ship-cloud-wiki.yml`.
* **No bottom nav** (declared in `1_cicd/src/data/nav-shape.json::no_bottom`). The shell is the fleet's: `libs:ui-nav-bars` (first row with Profile and Configs, the collapsed left side menu in `vertical_side_menu` mode, the top subpage tabs), `libs:theme-background`, `libs:ui-kit`. The side menu is `build.json::ui`, #1867 generated from the content repo's menu: three parents, Modern Science (hubs Sciences, Humanities, Arts, Explore over thirteen topics and the Graph), Arcanum Science (hubs A, B, C of the Esoteric Arcanum taxonomy over eleven sections and 79 pages) and Projects (Chronos, Sacred Geometry).
* **Topics**: Math, Computer Science, Physics, Astronomy, Engineering (one subpage per major field), Medicine, Anthropology, Human Belief Systems, Chronos, Art, Theater, Music, Movies. Each topic has an Overview tab and one tab per subpage.
* **Pages** are Markdown (headings, paragraphs, bullets, `**bold**`, `*italic*`, `[[topic.slug]]` links) with tag chips. Tapping a chip filters every page of the wiki by that tag (all selected tags must match).
* **Graph** (`libs:graph-view`, shared by reference so Cloud Notes can draw the same graph): pages are nodes coloured by topic, solid edges for `[[links]]`, faint edges for shared tags, force-directed layout, pan, pinch zoom, tap a node to open the page.
* **Content is a runtime dataset**, not an APK asset: `data/fleet/app/com.diegonmarcos.cloudwiki/wiki.json`, listed in `data/fleet/manifest.json::apps`, served by Cloud Store and read through `libs:fleet-data-client` (`WikiStore`). Edit the JSON to change the pages; topics added to it must also be declared in `build.json::ui` (the side menu).
* **#1867 the content is the repo [diegonmarcos/Projects-Library-KG](https://github.com/diegonmarcos/Projects-Library-KG)** (served by GitHub under its former name lib-chronos for now): one numbered folder per node (`1.Modern-science/1.0.Science/1.0.0.Math/1.0.0.0.Algebra/index.md`, `2.Arcanum-science/...`, `3.Projects/3.0.Chronos`, `3.Projects/3.1.Sacred-geo`), its root `wiki.json` generated by the repo's `tools/gen-wiki.py`. The app clones it read-only at run time (`ChronosRepo`, kept for offline use) and reads the pages from the clone; Cloud Store's runtime dataset `wiki` (the same file at the pin) serves until the first clone. `tools/regen-chronos.py` writes that dataset and the side menu from the repo at the pin.
* **Chronos simulators, baked as the offline seed (#1789)**: every page of the repo's `3.Projects/3.0.Chronos/` (root, 0 Humansphere, 1 Earthsphere, 2 Milkwaysphere, 3 Quantum Cycles with 3.0 Decoherence and 3.1 Quantum Gravity, 4 Astronomy) is a nested page under Chronos, in the repo's hierarchy and with its `<title>`s, shown in the fleet web view (`libs:web-core`, `WebProfile.APP_PAGE`, `ui/ChronosPage.kt`). The files are served offline from `app/src/main/assets/chronos` by `WebViewAssetLoader` on the asset origin, so relative links work; every other request is answered 403 and links off the origin open in the phone's browser. The CDN scripts, styles and fonts the pages use are vendored with sha256 pins.
  * Pin: `tools/chronos-pin.json` (`commit`). Regenerate: `python3 tools/regen-chronos.py`; move the pin: `python3 tools/regen-chronos.py --pin main`; drift check: `python3 tools/regen-chronos.py --check` (run by `test/test-chronos.sh` in the ship workflow, with the tree guard: the declared Chronos pages must equal the baked page tree). Never edit `assets/chronos` or the nested declaration by hand.
* Deep links (string extras on the launch intent): `page` (a topic id or `graph`), `tab` (a page id), `tags` (comma list), e.g. `--es page eng --es tab eng.civil`.
* No network permission of its own.
