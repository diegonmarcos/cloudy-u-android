# Cloud Canvas

A paint app and a music mixer (#1780). Tile `Canvas` sits in Cloud > Apps > Primary (Tools · Primary), right after Camera.

* Package `com.diegonmarcos.cloudcanvas`, image `cloud-canvas`, asset `Cloud-Canvas.apk`, ship workflow `ship-cloud-canvas.yml`.
* **Bottom nav Draw | Play** (`build.json::ui`, default Draw); since #1808 **Draw | Painter | Play | Draw Enhancer | Music Enhancer** (Painter inserted right after Draw, nothing else moved).
* **Draw** (page Draw): the shared Compose canvas, no WebView. Brush, pencil, marker, eraser, fill, line, rectangle, ellipse, text, eyedropper; colour picker with recent colours, size and opacity; layers (add, hide, reorder, opacity); undo/redo; pinch zoom and pan; canvas size presets; stylus pressure; open a picture to paint over; export PNG to a folder chosen through SAF; share. The document is immutable `DocState` snapshots (undo = the previous snapshot); each layer is the replay of its ops onto a bitmap; the PNG is `Pixels.composite` + `PngEncoder` (pure Kotlin).
* **Draw > Board** (#1787, second row Draw | Board): an infinite whiteboard in the fleet web view (libs:web-core `CloudWeb.create(.., WebProfile.APP_PAGE)`, hardware-accelerated). The engine is **Quickdraw** (MIT, `@quickdrawjs/core` 0.3.0, plain browser ESM, no build step), **vendored** in `app/src/main/assets/board` and served over WebViewAssetLoader at `https://appassets.androidplatform.net/board/`, so it works with no network; a link off the page (the engine's corner mark) opens in the browser. Boards are engine store snapshots in app storage (`files/boards/<id>.tldr`, `board/BoardStore.kt`), saved through `board/quickdraw/cloud-board-bridge.js` over a web message listener allowed for the asset origin and the main frame only. **Why not tldraw**: the brief's first choice, the fleet's tldraw 5.2.3 build (cloudy-h-webapps-desk `c_Suite/tldraw`), does not render in a production build without a licence key (its LicenseProvider replaces the editor after 5 s; the published Suite page is blank too). It is kept pinned in `vendor/tldraw` (not shipped) so Board can move back once the Suite build carries a key for the app's origin. Vendored, not fetched by CI: a pinned copy keeps the build reproducible; `PIN.json` in each copy records every file's sha256 and URL, `tools/vendor-board.py fetch quickdraw|tldraw` re-pins, `check` runs in the tester.
* **Painter** (#1808, its own bottom-nav section right after Draw): the owner's "Interactive Hexagon Grid" prototype, a Three.js r128 page in the fleet web view (libs:web-core `CloudWeb.create(.., WebProfile.APP_PAGE)`), served from `app/src/main/assets/painter` over WebViewAssetLoader at `https://appassets.androidplatform.net/painter/`, so it works with no network. Hex, square, triangle and octagon (+ small square gap tiles) grids of R=25 logical cells; each cell is an outline InstancedMesh (white, opacity 0.25) and a fill InstancedMesh at 0.94 scale lifted by 1 (black when empty); 2D (orthographic, frustum 1500) or 3D Sphere (perspective, radius scale*30, cells facing outward); OrbitControls (damping 0.05; pan in 2D View, rotate in 3D View, off in Paint and Rubber); Paint | Rubber | View, Grid Scale 15-100, six colours, Active Cells, Clear (the shape on screen), Center. Plain CSS in the Canvas colours, Inter bundled. `grid.js` is the pure half (generators, state, strokes, persistence codec), `painter.js` the Three.js half. Three.js, OrbitControls and Inter are **vendored** in `assets/painter/vendor`, pinned by `PIN.json` (`tools/vendor-painter.py fetch|check`). The state (painted cells per shape, colour, mode, scale, 2D/3D) is saved to `files/painter/painter.json` (`painter/PainterStore.kt`, atomic, validated) through the `CloudPainter` web message listener (asset origin, main frame only). Launch extras `section painter` plus `shape`, `layout`, `mode`, `color`, `scale` are handed to the page as overrides. The page takes no back gesture of its own (no history, no modal) and the shell clears the status bar.
* **Play**: a **sampled** grand piano and acoustic kit (#1787, `audio/Samples.kt`, `audio/SampleLoader.kt`) and the synth (`audio/Synth.kt`), through a low-latency AudioTrack (`PERFORMANCE_MODE_LOW_LATENCY`, native rate and burst). Mixer of 4 to 8 tracks with volume, pan, mute, solo and a loop recorder (notes stored in beats, so a tempo change re-times them), tempo, metronome, transport, WAV export (`OfflineMix` + `WavEncoder`).
* **Permissions**: none. No microphone (loops are recorded as notes), no storage permission (SAF), no network.
* **Sounds** (#1787): Salamander Grand Piano V3 (Alexander Holm, CC-BY 3.0): 30 roots every 3 semitones x 3 velocity layers, mono Ogg Vorbis, 3.3 MB; pitch-shifted between roots. MuldjordKit (Lars Muldjord, FreePats edition, CC-BY 4.0): kick, snare, hats closed/open, three toms, crash, ride, 3 layers each, 0.6 MB. Decoded once (MediaExtractor/MediaCodec) into 16-bit PCM and mixed by the same engine as the synth, so recorded loops and the WAV export use the samples; 64-voice polyphony (oldest stolen); velocity picks the layer and the gain (from the strike point on the key or pad). The synthesized piano and kit stay as the fallback while decoding, and Clap stays synthesized. Sources, the per-file mapping and the edits are in `assets/samples/*/NOTICE.md`; every file is in `licenses/curated.json` (licence, source URL, attribution); the attribution is shown in Configs > About > Credits.
* **Corner fix** (#1787): the Music Enhancer placeholder used to be greyed by a translucent box over the last 22% of the whole bottom-bar slot, which drew a dark block in the bottom-right corner of every page; the glyph is now dimmed inside the island (`DimPainter`).

## Draw Enhancer and Configs > AI (#1782)

* Bottom nav is Draw | Play | Draw Enhancer | Music Enhancer. Music Enhancer is a coming-soon placeholder (its entry is veiled grey).
* **Draw Enhancer**: input an uploaded picture or the current drawing; pick a preset (Simple enhance, Convert to 3D, Photorealistic, Line art clean-up, Colourize) or write a prompt. Each preset expands to a long professional prompt, shown in an expandable, per-run editable panel. The presets, qualities, sizes and limits are the runtime dataset `data/fleet/app/com.diegonmarcos.cloudcanvas/enhance-presets.json` (served by Cloud Store, read through libs:fleet-data-client), not code. The request (prompt plus image as one multimodal message) goes to OpenRouter through libs:ai's contract and HTTP; the result shows beside the original with Save PNG (SAF) and Send back to Draw (a new layer). Progress, errors, offline and a per-run cost cap are handled.
* **Configs > AI** (an own tab of the fleet Configs strip): the OpenRouter key (own override in `canvas_ai_secret`, EncryptedSharedPreferences; otherwise the run goes through the fleet's decisions engine, #1799: `DecisionsLink.image` sends the picture, the prompt and the model, and the engine holds the fleet Account's key, so this app never reads it; masked, never logged or exported), a model per task from the fleet catalogue's image models (libs:model-catalogue), output quality, size and the cost cap.
* Tests: `EnhanceTest` (preset expansion, per-task model persistence, key masking and a no-log source scan, request builder and answer parser, cost cap), `NavShapeTest`.
